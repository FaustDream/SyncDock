# 最近失败仓库查看设计

## 背景

当前 SyncDock 已支持：

- 查看最近日志
- 记录每次同步的逐仓库结果

但排查问题时，用户需要从完整日志中手动查找失败项，不够直接。

## 目标

新增一个独立菜单项，用于查看最近一次同步日志中的失败仓库列表，并显示失败原因。

## 需求范围

- 保留现有“查看最近日志”功能和输出格式
- 新增“查看最近失败仓库”菜单项
- 仅读取最近一份日志文件
- 只提取失败仓库，不展示已跳过、无效、无需同步项
- 如果最近日志没有失败仓库，输出明确提示
- 如果没有任何日志，沿用“暂无日志”语义

## 非目标

- 不新增单独的失败日志文件
- 不改变现有同步结果日志格式
- 不实现按历史日志检索失败项
- 不解析 Git 输出中的具体文件级失败信息

## 方案

### 日志层

在 `syncdock/log_service.py` 中新增最近失败仓库读取能力：

- 复用“最近一份日志”的定位逻辑
- 从日志文本中提取形如 `仓库名: 同步失败...` 的行
- 返回面向终端显示的文本结果

日志仍然保持仓库级解析，不引入更复杂的结构化日志格式。

### 菜单层

在 `syncdock/menu.py` 中新增菜单项：

- 文案：`查看最近失败仓库`
- 行为：调用日志层的新函数并直接输出

原有“查看最近日志”功能保持不变。

## 输出规则

有失败仓库时：

- 第一行显示最近日志文件名
- 后续显示失败仓库列表，每行一个仓库及其失败原因

无失败仓库时：

- 显示最近日志文件名
- 明确提示：`最近一次同步没有失败仓库`

无日志时：

- 显示：`暂无日志`

## 测试策略

补充日志/菜单相关测试，覆盖：

1. 最近日志中存在失败仓库时，能正确提取失败项
2. 最近日志中不存在失败仓库时，返回明确提示
3. 菜单映射新增选项后，能调用最近失败仓库查看逻辑
