## 一、技术栈选型

### 1.1 桌面应用框架

**选择：Tauri**

**理由**：
- 轻量：打包体积小（~10MB），内存占用低
- 安全：Rust 后端，内存安全有保障
- 跨平台：支持 Windows、macOS、Linux
- 性能：原生性能，接近桌面应用体验
- 生态：Rust 生态成熟，库丰富

**备选方案**：
- Electron：体积大（~150MB），资源占用高
- Flutter Desktop：生态不够成熟

### 1.2 前端框架

**选择：React 18 + TypeScript**

**理由**：
- React 生态成熟，组件库丰富
- TypeScript 提供类型安全
- Hooks API 简洁易用
- 社区活跃，问题易解决

### 1.3 构建工具

**选择：Vite**

**理由**：
- 开发启动快，热更新迅速
- 配置简单，开箱即用
- 生产构建优化好
- 与 Tauri 集成良好

### 1.4 后端语言

**选择：Rust**

**理由**：
- 内存安全，无 GC 停顿
- 性能优秀，接近 C/C++
- 错误处理严格，不易隐藏 bug
- 并发模型安全

## 三、数据流设计

### 3.1 状态流向

```
用户操作 → 前端事件 → Tauri Command → Rust 处理 → 
返回结果 → 前端更新 → UI 渲染
```

### 3.2 实时更新

同步任务执行时，通过 Tauri Event 实现实时状态推送：

```
Rust Task → Event Emitter → Frontend Listener → UI Update
```

## 四、核心技术实现

### 4.1 Git 命令执行

**设计原则**：
- 使用 `std::process::Command` 执行 Git 命令
- 统一错误处理与超时控制
- 日志记录完整命令与输出

**关键点**：
- 命令超时控制（默认 60s）
- 中文路径兼容
- 权限不足处理
- SSH/HTTPS 鉴权兼容

### 4.2 同步流程状态机

```
Idle → Checking → Fetching → Comparing → Pulling → Success
  ↓                                ↓
Skipped                          Failed
```

**状态转换条件**：
- Checking：检查仓库状态
- Fetching：执行 git fetch
- Comparing：比较本地与远端
- Pulling：执行 git pull --ff-only
- Success：同步成功
- Skipped：跳过（有改动、无 upstream 等）
- Failed：同步失败

### 4.3 并发控制

**设计**：
- 使用 `rayon` 进行并行处理
- 可配置并发数（默认 4）
- 任务队列管理
- 单仓库失败不影响其他

**实现要点**：
- 全局任务锁（防止重复执行）
- 进度实时反馈
- 任务取消支持

### 4.4 配置持久化

**存储位置**：
- Windows: `%APPDATA%/com.syncdock.desktop/`
- macOS: `~/Library/Application Support/com.syncdock.desktop/`
- Linux: `~/.config/com.syncdock.desktop/`

**文件结构**：
```
config/
├── config.json          # 应用配置
├── repositories.json    # 仓库列表
└── tasks.json           # 任务历史
logs/
├── app.log              # 应用日志
└── task_YYYYMMDD_HHMMSS.log  # 任务日志
```

## 六、安全性设计

### 6.1 数据安全

- 本地配置加密存储（可选）
- 敏感信息不记录日志
- 配置文件权限控制

### 6.2 操作安全

- 默认保守策略
- 危险操作二次确认
- 操作日志可追溯

### 6.3 鉴权安全

- 不存储 SSH 密钥
- 不存储 HTTPS 凭证
- 依赖系统 Git 凭证管理
