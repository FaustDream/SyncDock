## 一、功能概览

SyncDock 是一款专为开发者设计的 Git 仓库批量同步工具，核心功能围绕"多仓库、自动化、可视化"展开。

### 核心价值
1. **批量操作** - 一键同步数十个仓库，告别逐个手动操作
2. **智能检测** - 自动识别仓库状态，提前发现潜在冲突
3. **可视化监控** - 清晰的仪表盘展示所有仓库状态
4. **跨平台支持** - 支持 Windows、macOS、Linux

## 二、功能模块详单

### 2.1 仓库管理模块

#### 2.1.1 仓库导入
**功能描述**: 扫描本地目录，自动识别 Git 仓库并批量导入

**操作路径**: `清单` → `导入仓库`

**使用方法**:
1. 点击"导入仓库"按钮
2. 选择包含多个仓库的父目录
3. 系统自动扫描子目录中的 `.git` 文件夹
4. 预览识别结果，勾选需要导入的仓库
5. 设置分组（可选）
6. 点击"确认导入"

**特性说明**:
- 支持递归扫描（最多3层子目录）
- 自动跳过已导入的仓库（基于路径去重）
- 支持手动输入单个仓库路径
- 导入时可批量设置分组

**界面元素**:
```
┌─ 导入仓库 ──────────────────────────┐
│ 选择目录: [C:\Projects] [浏览]      │
│                                      │
│ 发现 12 个仓库:                      │
│ ☑ repo-1    C:\Projects\repo-1      │
│ ☑ repo-2    C:\Projects\repo-2      │
│ ☐ node_modules (非Git仓库)          │
│                                      │
│ 分组设置: [默认分组 ▼]               │
│                                      │
│           [取消]  [确认导入]          │
└──────────────────────────────────────┘
```

---

#### 2.1.2 仓库列表查看
**功能描述**: 以表格或卡片形式展示所有仓库，支持多维度筛选

**视图类型**:
- **表格视图**: 紧凑展示，适合快速浏览大量仓库
- **卡片视图**: 详细展示，适合查看完整信息

**列字段说明**:
| 字段 | 说明 | 示例 |
|------|------|------|
| 仓库名 | 仓库文件夹名称 | `syncdock-core` |
| 分组 | 用户自定义分组 | `工作项目` |
| 分支 | 当前检出分支 | `main` |
| 最近同步 | 上次同步时间 | `04-06 14:30` |
| 结果 | 同步操作结果 | `已同步` / `失败` |
| 状态 | 当前仓库状态 | `正常` / `待同步` / `异常` |

**筛选条件**:
- **搜索**: 按名称/路径/分支模糊匹配
- **分组**: 下拉选择特定分组
- **状态**: 选择状态类型（全部/待同步/已同步/异常/失败）

**批量操作**:
- 全选当前筛选结果
- 批量同步选中仓库
- 批量删除仓库记录

### 2.2 同步功能模块

#### 2.2.1 批量同步
**功能描述**: 对选中的多个仓库执行 `git pull` 操作

**前置检查**:
1. 检查仓库是否有未提交的改动
2. 检查当前分支是否有 upstream
3. 检查是否存在冲突

**同步流程**:
```
开始同步
   ↓
前置检查
   ↓
[通过] ─→ 执行 git fetch
   ↓              ↓
[不通过] → 标记原因   检查远程更新
                      ↓
                   有更新 → git pull
                      ↓        ↓
                   无更新 → 标记"已是最新"
                             ↓
                         记录结果
                             ↓
                          更新UI
```

**同步结果类型**:
| 结果 | 说明 | 显示颜色 |
|------|------|----------|
| 已同步 | 成功拉取远程更新 | 绿色 |
| 已跳过 | 本地无更新或用户取消 | 灰色 |
| 同步失败 | 拉取失败（冲突/网络等） | 红色 |
| 已取消 | 用户主动取消 | 灰色 |

**并发控制**:
- 默认并发数: 5
- 可在设置中调整
- 失败重试: 最多2次

---

#### 2.2.2 单仓库同步
**触发方式**:
- 在仓库详情页点击"立即同步"
- 在列表中右键菜单选择"同步"

**特点**:
- 实时显示同步日志
- 同步完成后自动刷新状态

---

#### 2.2.3 定时同步
**配置项**:
- 启用/禁用定时同步
- 同步间隔（分钟）
- 同步时间范围（如仅工作时间）

**默认配置**:
```json
{
  "autoSyncEnabled": false,
  "autoSyncIntervalMinutes": 30,
  "syncDuringWorkHoursOnly": false,
  "workHoursStart": "09:00",
  "workHoursEnd": "18:00"
}
```

### 2.3 状态检测模块

#### 2.3.1 状态类型
**完整状态列表**:

| 状态 | 英文标识 | 说明 | 优先级 |
|------|----------|------|--------|
| 正常 | `NORMAL` | 无需同步，无异常 | 低 |
| 已同步 | `SYNCED` | 刚完成同步操作 | 低 |
| 待同步 | `NEEDS_SYNC` | 本地落后于远程 | 中 |
| 本地有改动 | `LOCAL_CHANGES` | 存在未提交的改动 | 中 |
| 未跟踪文件 | `UNTRACKED_FILES` | 存在未跟踪的新文件 | 低 |
| Detached HEAD | `DETACHED_HEAD` | 处于游离头状态 | 高 |
| 仓库异常 | `REPOSITORY_ERROR` | 仓库损坏或配置错误 | 高 |
| 同步失败 | `SYNC_FAILED` | 上次同步失败 | 高 |
| 处理中断 | `INTERRUPTED` | 同步过程被中断 | 中 |
| 未配置 upstream | `NO_UPSTREAM` | 当前分支无远程追踪 | 中 |
| 已禁用 | `DISABLED` | 用户手动禁用同步 | 低 |

---

#### 2.3.2 状态检测逻辑
```
检测流程:
1. 检查 .git 目录是否存在
   ↓
2. 检查 Git 命令是否可用
   ↓
3. 执行 git status --porcelain
   ↓
4. 检查是否有改动/未跟踪文件
   ↓
5. 检查 HEAD 是否 detached
   ↓
6. 检查当前分支的 upstream
   ↓
7. 执行 git fetch --dry-run 检查远程更新
   ↓
8. 综合判定最终状态
```

### 2.5 设置模块

```
设置项:
├─ 同步设置
│  ├─ 自动同步开关
│  ├─ 同步间隔（分钟）
│  ├─ 最大并发数
│  └─ 失败重试次数

   ├─ 日志级别
   └─ 数据存储路径
```

---

#### 2.5.2 同步策略配置
**全局策略**:
```json
{
  "strategy": "rebase",
  "autoStash": true,
  "skipSubmodules": false,
  "pruneRemote": true
}
```

**单仓库策略**（优先级更高）:
- 可对特定仓库单独配置
- 支持继承全局配置

## 五、性能指标

### 5.1 扫描性能
- 单仓库扫描耗时: < 100ms
- 批量扫描（100个仓库）: < 3s

### 5.2 同步性能
- 单仓库同步耗时: 1-5s（取决于网络和仓库大小）
- 并发同步效率: 接近线性增长（受限于网络带宽）
