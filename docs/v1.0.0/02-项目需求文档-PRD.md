## 1. 项目概述

### 1.1 项目名称

- 中文：同步坞
- 英文：SyncDock

### 1.2 产品定义

同步坞是一款桌面端多 Git 仓库管理与批量同步工具，用于帮助用户在多台设备之间更高效、更稳定地保持多个独立仓库处于最新状态。

### 1.3 项目目标

- 提供统一的多仓库管理入口
- 支持一键同步全部仓库
- 默认采用稳定、保守的同步策略
- 将结果清晰呈现给用户
- 降低日常跨设备切换的操作摩擦

---

## 2. 背景与问题

### 2.1 用户现状

用户存在多台办公设备，且多个项目或资料分散在不同 Git 仓库。当前需要手动逐仓库进入本地目录执行同步，操作频繁且机械。

### 2.2 当前问题

- 仓库数量多，重复操作明显
- 手动同步容易遗漏
- 某些仓库有本地改动时，人工判断成本高
- 通用 Git GUI 不聚焦批量同步这个场景
- 缺乏统一的成功、失败、跳过结果视图

---

## 3. 用户画像

### 3.1 核心用户

- 同时维护多个仓库的个人开发者
- 双设备或多设备办公用户
- 需要同步代码与文档资产的用户

### 3.2 使用习惯

- 日常使用 Git 但不希望频繁打开命令行
- 更在意稳定性和低摩擦，而不是复杂高级功能
- 愿意一次配置，长期复用

---

## 4. 核心场景

### 4.1 下班回家一键同步

用户在笔记本完成提交并 push，回到台式机后打开同步坞，点击"同步全部"，批量拉取所有仓库最新内容。

**预期结果**：
- 所有可同步仓库自动拉取最新代码
- 有改动的仓库自动跳过并提示
- 失败仓库给出明确原因

### 4.2 查看异常仓库

用户需要快速判断哪些仓库因为本地修改、鉴权失败、网络异常或 upstream 缺失而未能同步。

**预期结果**：
- 状态筛选器快速过滤异常仓库
- 详情面板显示具体原因和建议操作
- 日志可导出用于详细排查

### 4.3 新增仓库纳入管理

用户克隆了新仓库，希望通过扫描目录或手动添加方式纳入统一管理。

**预期结果**：
- 扫描功能自动识别目录下的 Git 仓库
- 批量导入并自动分配到指定分组
- 重复仓库自动去重

### 4.4 按分组同步

用户希望只同步"工作"或"文档"仓库，而非所有仓库。

**预期结果**：
- 分组切换后快速定位目标仓库
- 一键同步当前分组
- 分组管理支持增删改

## 5. 产品定位与边界

### 5.1 产品定位

同步坞是一个**批量同步调度器和仓库状态工作台**。

### 5.2 产品边界

首版不承担以下职责：

- 代码编辑
- 完整 Git 图谱展示
- 自动 commit
- 自动 push 所有仓库
- 自动解决冲突
- GitHub 云端账号管理
- 团队协作平台能力

---

## 6. 核心需求

### 6.1 仓库管理

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 手动添加本地仓库 | P0 | 选择本地目录添加为仓库 |
| 指定根目录自动扫描 | P0 | 递归扫描识别 Git 仓库 |
| 编辑名称、备注、分组 | P0 | 修改仓库元信息 |
| 启用/禁用仓库 | P0 | 禁用后不参与同步 |
| 删除仓库 | P0 | 从列表移除，不删除本地文件 |
| 仓库去重 | P0 | 避免重复添加相同路径 |

### 6.2 仓库状态识别

每个仓库需至少识别以下信息：

| 状态项 | 说明 |
|--------|------|
| 仓库是否有效 | 路径存在且为 Git 仓库 |
| 当前分支 | 分支名称 |
| 是否存在本地未提交修改 | 工作区状态 |
| 是否存在未跟踪文件 | untracked files |
| 是否领先远端 | ahead count |
| 是否落后远端 | behind count |
| 是否配置 upstream | 跟踪分支配置 |
| 最近同步时间 | 上次同步的时间戳 |
| 最近同步结果 | 成功/失败/跳过及原因 |

### 6.3 批量同步

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 同步全部启用仓库 | P0 | 一键同步所有启用仓库 |
| 同步选中仓库 | P0 | 手动选择后批量同步 |
| 按分组同步 | P1 | 仅同步指定分组 |
| 显示同步进度 | P0 | 实时展示进度条和状态 |
| 显示任务汇总结果 | P0 | 成功/失败/跳过统计 |

### 6.4 单仓库同步

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 单仓库手动同步 | P0 | 在详情页触发单个仓库同步 |
| 查看单仓库详细日志 | P0 | 展示该仓库的同步日志 |

### 6.5 日志与结果追踪

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 记录每次同步任务 | P0 | 持久化任务历史 |
| 记录每个仓库的结果 | P0 | 成功/失败/跳过及详情 |
| 支持查看错误摘要 | P0 | 快速定位失败原因 |
| 支持复制日志文本 | P1 | 导出日志用于分析 |
| 日志自动清理 | P1 | 按天数自动清理旧日志 |

### 6.6 配置管理

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 导出仓库配置 | P1 | 备份仓库列表和设置 |
| 导入仓库配置 | P1 | 恢复或跨设备迁移 |
| 路径前缀替换 | P1 | 迁移时批量调整路径 |
| 配置冲突处理 | P1 | 导入时的冲突解决策略 |

## 7. 非功能需求

### 7.1 稳定性

- 默认不破坏本地工作区
- 单仓库失败不影响其他仓库
- 主界面不可被同步任务阻塞
- 异常退出后日志尽量可恢复

### 7.2 性能

- 首版支持管理 100 个以内仓库
- 同步任务采用有限并发（默认 4）
- 状态刷新与同步执行分离
- 命令执行有超时控制

### 7.3 易用性

- 首次使用流程简单（< 5 分钟）
- 操作文案明确
- 错误提示友好且具体
- 支持中文和英文界面

### 7.4 可维护性

- Git 执行层与 UI 分离
- 配置结构清晰可扩展
- 后续支持高级策略时不推翻现有架构
- 日志详细便于排查

## 8. MVP 范围

### 8.1 首版必须具备

- [x] 仓库扫描
- [x] 仓库添加与删除
- [x] 仓库状态检测
- [x] 一键同步全部
- [x] 单仓库同步
- [x] 日志记录
- [x] 跳过保护策略
- [x] 本地配置持久化
- [x] 分组管理
- [x] 配置导入导出

### 8.2 首版不做

- 自动 push
- 自动 stash / rebase
- 冲突自动解决
- 云同步配置
- 插件系统

---

## 9. 验收标准

满足以下条件即视为首版可用：

1. 用户可将多个仓库纳入同步坞统一管理
2. 用户可一键同步全部仓库
3. 本地脏工作区默认不会被误处理
4. 异常仓库能给出明确原因
5. 整体操作明显优于逐仓库手工 pull
6. 配置可导入导出，支持跨设备迁移
7. 日志可追溯，问题可定位
