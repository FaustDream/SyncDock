## Quick Start

### Installation

1. Download the latest release
2. Windows: Double-click `.msi` file to install
3. macOS: Drag the app to Applications folder
4. Linux: Install using `.deb` or `.rpm` package

### First-time Setup

1. Ensure Git is installed (version ≥ 2.0)
2. Launch SyncDock
3. Click "Scan Import" or "Add Repository"
4. Select local repository directory
5. Start using

## Features

### Repository Management

#### Scan Import

**Purpose**: Automatically scan local directories to identify Git repositories

**Steps**:
1. Click "Scan Import" button
2. Select root directory to scan
3. Set scan depth (default: 4 levels)
4. Click "Start Scan"
5. Check repositories to import
6. Set name and group for each repository
7. Click "Import Selected"

**Tips**:
- Duplicate repositories are automatically skipped
- Group related repositories together

#### Add Repository

**Purpose**: Manually add a single repository

**Steps**:
1. Click "Add Repository" button
2. Select repository directory
3. Set name, group, and notes
4. Click "Add"

#### Clone Repository

**Purpose**: Clone a new repository from remote URL

**Steps**:
1. Click "Add Repository" → "Clone Repository"
2. Enter remote URL
3. Select destination directory
4. Set name and group
5. Click "Clone"

### Sync Functions

#### One-Click Sync

**Purpose**: Sync all enabled repositories

**Steps**:
1. Click "Sync All" button (top right)
2. View sync progress
3. Check result statistics when complete

**Skip Scenarios**:
- Uncommitted changes exist
- Upstream not configured
- Rebase/merge in progress
- Detached HEAD state

#### Group Sync

**Purpose**: Sync only specified group

**Steps**:
1. Switch to target group
2. Click "Sync Current Group"

#### Selected Sync

**Purpose**: Sync checked repositories

**Steps**:
1. Check repositories in list view
2. Click "Sync" button

### Status View

#### Repository Status

**Status Types**:
- **Normal**: Synced or no sync needed (Green)
- **Modified**: Uncommitted changes (Yellow)
- **Pending Sync**: behind > 0 (Yellow)
- **Error**: Repository damaged or error (Red)
- **Skipped**: Skipped by protection rules (Gray)
- **Syncing**: In progress (Blue)

#### Detail View

Click repository name to view:
- Basic info (path, branch, remote)
- Sync results
- Recent logs
- Quick actions

---

### Settings

#### General

- **Default View**: Page shown at startup
- **Theme Mode**: Light/Dark/Follow System
- **Language**: Chinese/English

#### Sync Settings

- **Concurrency**: Number of simultaneous syncs (default: 4)
- **Timeout**: Command execution timeout in seconds (default: 60)
- **Skip Untracked**: Skip repositories with untracked files
- **Debug Logs**: Record detailed debug information

#### Paths

- **Config Directory**: Configuration file location
- **Logs Directory**: Log file location
- **Default Scan Directory**: Default starting directory for scans

---

### Config Import/Export

#### Export Config

**Purpose**: Backup repository list and settings

**Steps**:
1. Go to "Settings" → "Repositories"
2. Click "Export Config"
3. Select save location
4. Generate JSON file

#### Import Config

**Purpose**: Restore or migrate configuration

**Steps**:
1. Go to "Settings" → "Repositories"
2. Click "Import Config"
3. Select config file
4. Preview conflicts and changes
5. Choose import strategy (merge/overwrite)
6. Confirm import

**Cross-device Migration**:
1. Export config on original device
2. Import config on new device
3. Use "Path Prefix Replacement" to adjust paths

## FAQ

### Q: Why was repository skipped?

**Possible Reasons**:
1. Uncommitted changes - Commit or stash first
2. Upstream not configured - Set upstream branch manually
3. Rebase/merge in progress - Complete or abort operation
4. Detached HEAD - Switch back to normal branch

### Q: How to handle authentication failure?

**SSH Method**:
1. Check if SSH key is configured
2. Ensure ssh-agent is running
3. Test SSH connection: `ssh -T git@github.com`

**HTTPS Method**:
1. Check if credentials are expired
2. Update Git Credential Manager
3. Re-enter username and password

### Q: How to update repository path?

Repository path cannot be modified directly. You need to:
1. Delete the original repository record
2. Re-add with new path

### Q: Can logs be deleted?

Yes, logs are automatically cleaned by configured days (default: 30 days).
You can also manually clean in "Settings" → "Paths".

## Best Practices

### Repository Grouping

- **Work**: Work-related projects
- **Personal**: Personal projects
- **Docs**: Documentation repositories
- **Config**: Configuration file repositories

### Sync Strategy

1. **Regular Sync**: Sync once when starting work each day
2. **Check Status**: Check for changes before syncing
3. **Handle Exceptions**: Deal with skipped/failed repositories promptly
4. **Backup Config**: Export config backup regularly
