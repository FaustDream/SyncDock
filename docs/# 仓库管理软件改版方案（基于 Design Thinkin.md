# 件改版方案（基于 Design Thinking）

# 1. Empathize 阶段

## 1.1 目标用户与使用场景

### 目标用户
1. **普通仓库使用者**
   - 需要快速添加仓库、同步仓库、查看状态
   - 不关心底层命令执行过程，只关注结果是否成功

2. **批量管理仓库的运维/开发人员**
   - 常常需要同步全部、按分组同步、强制覆盖同步
   - 更关注任务进度、失败仓库、跳过原因、日志完整性

3. **管理者/高级用户**
   - 需要查看任务历史、日志、版本更新、同步模式配置
   - 更关注可控性、可追踪性、稳定性

## 1.2 用户痛点

1. **执行过程中无反馈**
   - 添加仓库、同步仓库、刷新状态时没有明确进度提示
   - 用户会误认为页面卡死

2. **频繁弹出 CMD 窗口**
   - 影响体验，造成“程序不稳定”的感知
   - 干扰用户操作与注意力

3. **信息布局重复或低效**
   - 任务页重复展示成功/失败/跳过信息
   - 仓库路径、分组、权限等布局不够简洁

4. **任务状态流转不完整**
   - 运行中任务结束后未自动切换为“已完成”
   - 导致用户对执行结果产生疑惑

5. **系统整体卡顿**
   - 软件启动慢、界面切换卡、操作阻塞
   - 用户信任感下降

## 1.3 用户洞察（模拟访谈/观察）

| 编号 | 用户洞察 |
|---|---|
| 1 | 用户更希望看到“正在执行什么 + 还剩多少”而不是静态等待。 |
| 2 | 弹出命令行窗口会被理解为“非正式、低质量”的桌面软件体验。 |
| 3 | 批量同步任务中，用户最关心的是“当前执行哪个仓库、完成了几个、失败了哪些”。 |
| 4 | 在添加仓库时，默认填写“显示名称=仓库名称”可明显减少输入成本。 |
| 5 | 分组更适合“可选已有分组 + 支持直接新建输入”的组合输入方式。 |
| 6 | 仓库列表页应强调“核心操作”，非必要信息如路径应收起到详情页。 |
| 7 | 用户需要“强制同步”来解决本地脏状态导致的一直跳过问题。 |

# 2. Define 阶段

## 2.1 用户中心问题定义

**How Might We：如何在不增加用户认知负担的前提下，重构仓库、任务、设置界面，使仓库操作更流畅、同步过程更可视、任务结果更清晰，同时消除 CMD 弹窗与卡顿问题？**

## 2.2 核心挑战

1. **长耗时操作缺乏状态反馈**
2. **后台执行方式导致 CMD 窗口频繁弹出**
3. **页面信息层级混乱，存在重复展示**
4. **批量任务流程缺少统一任务中心承接**
5. **同步策略不足，缺少强制覆盖云端到本地能力**
6. **启动性能与交互流畅度不足**

## 2.3 机会点

1. 统一引入 **任务队列 + 进度组件**
2. 后台执行全部改为 **静默子进程**
3. 列表页做减法，详情页做承载
4. 用 **导航型分组栏** 提升分组操作效率
5. 引入 **强制同步模式**
6. 从渲染、数据、日志三个层面优化性能

# 3. Ideate 阶段

## 3.1 方案脑暴

### A. 仓库添加体验优化
1. **添加仓库时显示加载弹层**
   - 变体A：圆形加载动画
   - 变体B：进度条 + 当前步骤文本
   - 变体C：滚动日志输出面板

2. **添加仓库默认填充显示名称**
   - 变体A：自动取仓库名
   - 变体B：允许用户编辑后覆盖
   - 变体C：失焦时自动同步一次

3. **分组输入升级为“可选可输”**
   - 变体A：Select + 可输入
   - 变体B：Autocomplete
   - 变体C：下拉候选 + Enter 新建

4. **表单排版优化**
   - 变体A：备注与按钮留 16px 间距
   - 变体B：按钮区独立 footer
   - 变体C：表单双列改单列

### B. 仓库界面重构
5. **分组改顶部导航栏**
   - 变体A：Tab 导航
   - 变体B：可横向滚动导航
   - 变体C：最右侧加号新建分组

6. **仓库卡片精简字段**
   - 变体A：仅显示名称、分组、状态
   - 变体B：路径移至详情页
   - 变体C：组标签直接显示分组名文本

7. **搜索、分组、状态筛选同一行**
   - 变体A：三栏等宽
   - 变体B：搜索框更长
   - 变体C：响应式折行

8. **权限改为总选择框**
   - 变体A：Checkbox 全选/取消全选
   - 变体B：半选态
   - 变体C：右侧同步按钮缩小

9. **增加强制同步操作**
   - 变体A：强制同步全部
   - 变体B：强制同步当前分组
   - 变体C：强制同步单仓库

### C. 任务界面优化
10. **统一跳转到当前任务页执行**
   - 变体A：批量任务自动跳转
   - 变体B：显示当前仓库、队列进度
   - 变体C：每完成一个自动更新计数

11. **任务状态自动流转**
   - 变体A：运行中 → 已完成
   - 变体B：运行中 → 部分失败
   - 变体C：运行中 → 失败/取消

12. **去重任务摘要信息**
   - 变体A：保留顶部统计
   - 变体B：去掉重复按钮式计数
   - 变体C：日志中仅保留明细

13. **历史任务详情独立窗口**
   - 变体A：点击历史记录打开详情弹窗
   - 变体B：新页面详情
   - 变体C：侧边抽屉查看

### D. 设置与系统体验
14. **关于页增加检查更新**
   - 变体A：手动检查
   - 变体B：启动时检查
   - 变体C：发现新版本跳转 GitHub Releases

15. **同步模式扩展**
   - 变体A：安全同步
   - 变体B：普通同步
   - 变体C：强制覆盖同步

16. **启动加载动画 + 性能优化**
   - 变体A：Splash 屏
   - 变体B：骨架屏
   - 变体C：分模块懒加载

17. **更换应用图标**
   - 变体A：猫咪站在小船上
   - 变体B：水波简笔 SVG
   - 变体C：圆角扁平图标风格

# 4. Prototype 阶段

## 4.1 原型 1：添加仓库弹窗重构

**目标：** 解决“慢、卡、表单不好用、CMD 弹窗”问题

**低保真原型结构：**
1. 仓库地址输入
2. 显示名称（默认自动填充仓库名）
3. 分组（可输入下拉框）
4. 备注
5. 底部按钮区：取消 / 添加仓库
6. 添加后显示“执行中弹层”
   - 当前步骤
   - 进度动画
   - 实时输出日志（可折叠）

**工具/实现：**
- React 18 + TypeScript
- Dialog / Combobox / Progress / Textarea
- 后端改为静默执行，不显示 CMD

**验证点：**
- 用户是否还会误认为卡死
- 表单填写步骤是否更少

---

## 4.2 原型 2：仓库页重构

**目标：** 强化分组导航、精简信息、突出操作

**低保真原型结构：**
1. 顶部：分组导航栏 + 最右侧“+”
2. 筛选栏一行：搜索框 / 分组框 / 状态框
3. 工具栏：刷新状态、同步全部、强制同步全部
4. 仓库列表：
   - 复选框
   - 仓库名
   - 分组名
   - 状态
   - 操作：同步 / 强制同步 / 详情
5. 底部：
   - 权限全选框
   - 缩小版同步按钮

**验证点：**
- 信息是否更聚焦
- 批量操作是否更顺手

---

## 4.3 原型 3：当前任务页重构

**目标：** 统一承接批量同步任务，提升过程可视性

**低保真原型结构：**
1. 顶部任务概览：
   - 已完成 x/x
   - 成功 x
   - 跳过 x
   - 失败 x
   - 不同颜色显示状态

2. 中部当前执行仓库：
   - 当前仓库名
   - 当前操作类型
   - 动画进度条

3. 下部实时日志
   - 默认显示全部日志
   - 可切换仓库日志

4. 历史任务列表
   - 点击后打开历史任务详情窗口

**验证点：**
- 用户是否能一眼判断任务进展
- 是否减少对重复信息的困惑

---

## 4.4 原型 4：设置页与启动体验

**目标：** 提升可配置性与专业感

**原型内容：**
1. 关于页：
   - 当前版本
   - 检查更新按钮
   - 检查到更新后跳转 GitHub 下载页
   - 不再显示配置目录/日志目录

2. 同步模式：
   - 普通同步：拉取并合并
   - 安全同步：有冲突时跳过
   - 强制同步：云端覆盖本地
   - 每种模式附说明文案

3. 目录设置：
   - 当前配置目录下方放提示与按钮
   - 当前日志目录下方放提示与按钮
   - 默认扫描目录下方放提示与按钮

4. 启动 Splash：
   - Logo + 加载动画 + “正在加载仓库与配置”

# 5. Test 阶段

## 5.1 测试方案

1. **添加仓库流程测试**
   - 观察是否还误判“卡死”
   - 测试默认显示名称是否正确填充

2. **无 CMD 弹窗测试**
   - 添加仓库、刷新状态、同步全部、分组同步、单仓库同步分别验证
   - 确保后台执行静默

3. **任务流测试**
   - 批量同步全部后是否自动跳转当前任务页
   - 每完成一个仓库后计数是否实时更新
   - 结束后是否自动改为已完成

4. **历史任务测试**
   - 点击历史任务是否正确打开详情窗口
   - 日期格式是否修正为正确格式，如 `yyyy/MM/dd`

5. **性能测试**
   - 冷启动时间
   - 首屏可交互时间
   - 仓库列表 100/500 项滚动流畅度
   - 日志渲染压力测试

## 5.2 预期反馈与改进方向

| 测试项 | 预期结果 | 可能改进 |
|---|---|---|
| 添加仓库 | 用户能理解正在执行中 | 增加步骤文本，如“正在克隆/读取配置/保存记录” |
| 无弹窗执行 | 用户感知更专业 | 增加失败时“查看详细日志”入口 |
| 当前任务页 | 用户更清楚批量任务进展 | 增加暂停/取消能力 |
| 仓库页重构 | 页面更简洁 | 对高频操作加快捷按钮 |
| 性能优化 | 卡顿减少 | 继续做虚拟列表、日志分片渲染 |

# 6. Summary and Iteration

## 6.1 最终推荐修改方案

### 仓库添加窗口
1. 添加仓库时增加加载动画/进度输出
2. 取消所有 CMD 弹窗，改后台静默执行
3. 显示名称默认填充仓库名称
4. 分组改为可输入下拉框，支持已有分组与新建分组
5. 按钮与备注拉开间距

### 仓库界面
1. 去掉“新建分组按钮”，改为分组导航栏右侧“+”
2. 刷新状态、同步操作全部取消 CMD 弹窗
3. 所有同步操作增加统一进度展示
4. 增加强制同步全部 / 当前分组 / 单仓库
5. 仓库组字段改为直接显示分组名称
6. 路径从列表页移除，仅详情页显示
7. 搜索框、分组框、状态框同一行
8. 权限改为全选选择框，同步按钮缩小
9. 日志默认显示全部日志

### 任务界面
1. 任务结束自动变更为已完成
2. 去掉重复的成功/跳过/失败按钮展示
3. 批量任务自动跳转当前任务页并显示执行动画
4. 去掉“运行摘要”
5. 合并仓库结果和任务详情
6. 历史任务点击后独立查看详情
7. 修正日期格式显示

### 设置界面
1. 关于页增加检查更新，命中后跳转 GitHub 下载页
2. 同步模式支持多种策略并附说明
3. 目录提示与按钮下移到对应路径项下面
4. 关于页不展示配置目录和日志目录

### 其他
1. 增加软件启动加载动画
2. 优化流畅度：
   - 列表虚拟滚动
   - 日志分批渲染
   - 路由懒加载
   - 减少阻塞式同步调用
   - 长任务统一走后台队列
3. 推荐前端 UI 组件：
   - **Ant Design**
   - **Arco Design**
   - **Semi Design**
   - **MUI**
   - **shadcn/ui + Radix UI**
4. 图标建议：
   - SVG 意象：**猫咪站在小船上，在水面漂流**
   - 风格：扁平、圆角、浅蓝水波、暖色猫咪

   - 修复任务完成状态

2. **第二阶段：界面重构**
   - 仓库页与任务页重排
   - 分组导航升级

3. **第三阶段：性能优化**

## 6.3 对 Design Thinking 的反思

Design Thinking 在本次改版中最大的价值，是**从用户感知出发，而不是只从功能出发**。  
用户真正痛苦的不是“没有某个按钮”，而是：
- 看不到进度
- 不知道是否卡住
- 任务结束不明确
- 信息重复且混乱
- 软件不流畅

其局限也存在：
- 需要产品、设计、前端、后端协同
- 多轮测试会增加时间成本
- 若缺少真实用户反馈，部分设计仍需迭代验证
