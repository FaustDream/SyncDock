# SyncDock v2.0.0 项目需求文档 PRD

## 一、背景

多仓库开发者在日常工作中需要频繁执行如下动作：

- 查看各仓库是否落后远端
- 判断本地是否有未提交或未跟踪改动
- 对全部仓库、分组仓库或单仓库执行同步
- 在同步失败后快速知道失败原因和错误码
- 导出和迁移本地仓库配置

传统命令行或多个 Git GUI 并用的方式切换成本高、状态分散，且日志和错误定位不统一。

## 二、产品目标

1. 提供统一的桌面化多仓库工作台
2. 保证耗时操作后台执行，不阻塞其他界面功能
3. 提供可解释的状态、结果和错误提示
4. 保证配置迁移、问题排查、日常使用都有稳定文档支撑

## 三、核心需求

### 3.1 仓库管理

- 支持手动添加仓库
- 支持编辑仓库名称、分组、归属、备注、启用状态
- 支持删除仓库
- 支持分组创建、查看和多选删除
- 删除分组时，组内仓库自动归到“未分组”

### 3.2 状态与同步

- 支持刷新全部仓库状态
- 支持刷新选中仓库状态
- 支持同步全部、分组同步、单仓库同步
- 支持强制同步
- 支持后台任务执行与任务取消

### 3.3 任务中心

- 概览显示当前任务与今日任务
- 历史任务支持搜索、结果筛选、日期筛选
- 任务日志支持搜索、级别筛选与导出
- 运行中的任务展示进度条与阶段日志

### 3.4 日志与错误

- 仓库日志中心默认显示全部仓库日志
- 选择仓库后切换到单仓库日志视角
- 日志中的 warning/error 必须展示错误码
- 支持日志导出

### 3.5 设置与迁移

- 支持同步策略、超时、并发、日志保留策略配置
- 支持日志目录与配置目录切换
- 支持仓库配置导入导出
- 支持关于页内版本查看、更新检查、问题反馈

## 四、非功能需求

- UI 在桌面端输入控件高度、按钮尺寸、信息密度上保持统一
- 滚动条默认隐藏，但滚动能力保留
- 前后端构建可重复执行
- 所有错误提示尽量带错误码、动作建议、可重试标记

## 五、验收标准

- 长时间同步或刷新时，界面仍可切换页面和执行其他操作
- 任务概览、任务历史、日志中心数据一致
- 仓库状态文案在总览与仓库页一致
- 设置页各输入控件尺寸统一
- 发布产物可生成安装版与免安装版
