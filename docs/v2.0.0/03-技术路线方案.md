# SyncDock v2.0.0 技术路线方案

## 技术栈

- 前端：React 18 + TypeScript + Vite
- 桌面框架：Tauri 1.x
- 后端：Rust
- 数据存储：本地 JSON 配置与任务/仓库记录

## 架构分层

### 前端层

- 页面层：`OverviewPage`、`RepositoriesPage`、`TasksPage`、`SettingsPage`
- 共享状态层：`AppContext`
- 适配层：`api.ts`
- 工具层：格式化、日志解析、状态映射、任务映射

### Tauri 命令层

- 应用快照获取
- 仓库 CRUD
- 后台刷新任务启动
- 后台同步任务启动
- 日志导出
- 配置导入导出

### Rust 核心层

- Git 状态检测
- 后台任务执行器
- 任务进度事件推送
- 错误模型与错误码
- 存储层

## 关键设计决策

### 1. 后台任务优先

刷新和同步都不直接阻塞 `invoke` 调用，而是：

- 先创建任务记录
- 立即返回前端
- 在后台线程执行
- 通过事件回传进度与结果

### 2. 结构化任务日志

任务不仅保存最终结果，还保留阶段日志：

- 开始
- 检查
- fetch
- compare
- pull / force
- 完成 / 失败 / 取消

### 3. 错误码与用户文案分离

每个错误都尽量同时具备：

- 错误码
- 面向用户的标题
- 说明文案
- 技术细节
- 建议动作
- 是否可重试

### 4. 本地配置可迁移

通过导入导出配置包保存：

- 设置
- 仓库记录
- 任务摘要

不导出实际仓库代码内容。

## 发布策略

- 开发构建：`npm run tauri dev`
- 生产构建：`npm run tauri build`
- 安装版：NSIS 安装包
- 免安装版：将生产 exe 与说明文件打成便携压缩包
